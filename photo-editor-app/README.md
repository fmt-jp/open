# PixelVeil(写真かくす加工・スマホ向け写真加工アプリ・MVP)

トリミング／EXIF情報の焼き込み／顔・ナンバープレートのモザイク・アイコン隠しを、
すべて**端末内(ブラウザ内)だけ**で行う写真加工アプリです。写真データを外部サーバーへ
アップロードする処理は一切含まれていません。

## 1. 採用技術と理由

| 項目 | 採用技術 | 理由 |
|---|---|---|
| 実行環境 | HTML/CSS/JavaScript + PWA(Progressive Web App) | ネイティブのビルド環境(Xcode/Android Studio)なしで、iPhone/Androidどちらのブラウザでも即動作。ホーム画面に追加すればアイコンから起動できネイティブアプリに近い体験になる |
| フレームワーク | 素のJavaScript(フレームワークなし) | Canvas APIを直接操作する処理が中心のため、フレームワークの抽象化がむしろ不要。依存を減らし軽量に保てる |
| EXIF読取 | [exif-js](https://github.com/exif-js/exif-js)(CDN読込) | JPEGのEXIFタグをブラウザ内だけで解析できる定番ライブラリ |
| 画像処理(トリミング/文字焼込/モザイク) | Canvas 2D API | ピクセル単位の合成・縮小拡大描画がすべて標準APIで完結し、外部通信が不要 |
| 顔検出 | [face-api.js](https://github.com/justadudewhohacks/face-api.js)(tinyFaceDetector, CDN読込) | TensorFlow.jsベースでブラウザ内(WebGL)推論が可能。**写真そのものは送信されず**、初回のみ学習済みモデルの重みファイルをダウンロードする(通信内容は写真ではなくモデルデータ) |
| ナンバープレート検出 | MVPでは手動指定のみ | 商用利用可・軽量なオープンモデルが少ないため。`hideRegions`にtype:'plate'を追加できる構造にしてあるので、将来カスタムモデルを`app.js`の検出処理に差し込むだけで対応可能 |
| 端末内処理の担保 | `fetch`/`XHR`による画像送信コードなし | 写真の読込(`File`→`Image`→`Canvas`)から保存(`canvas.toBlob`→ダウンロード)まで、すべてブラウザのメモリ内で完結 |

## 2. プロジェクト構成

```
photo-editor-app/
├── index.html    … 画面構造(写真選択画面 / 編集画面 / 各パネル)
├── style.css     … モバイル最適化スタイル(下部固定メニュー、タップ領域46px以上など)
├── app.js        … アプリのロジック本体(下記「主要処理」参照)
├── manifest.json … PWAマニフェスト(ホーム画面追加用)
├── sw.js         … 後始末用(過去にインストールされた古いキャッシュを解除するためだけの自己解除スクリプト)
├── icon.svg      … アプリアイコン
└── README.md     … 本ファイル
```

### app.js の主要処理
- `buildOriginalBase()` … 写真読込 + EXIF Orientation補正 + 長辺1600pxへの縮小(端末負荷対策)
- トリミング(3章) … ピンチ/ドラッグでCanvas描画元矩形(`state.crop`)を変更し、「適用」でクロップ確定
- EXIF焼き込み(4章) … `EXIF_FIELD_DEFS`で項目定義、`drawExifText()`でCanvasに直接文字を合成
- 顔・ナンバー隠し(5章) … `runAutoDetect()`でAI検出、`applyHideRegions()`でモザイク/アイコンを合成
- `renderFinal()` … 上記を「トリミング→EXIF→隠す」の順で毎回ソースから再合成(非破壊)
- 保存(7章) … `canvas.toBlob()`→ `<a download>` で端末にJPEGとしてダウンロード

## 3. ビルド方法

ビルド処理は不要です(静的ファイルのみ)。ただし `file://` で直接開くと `fetch`(Service Worker)や
一部ブラウザAPIが制限されるため、**簡易HTTPサーバー経由**での起動を推奨します。

```bash
cd photo-editor-app
python3 -m http.server 8080
# または: npx serve .
```

ブラウザで `http://localhost:8080` を開きます。

## 4. 実機へのインストール方法

1. 上記サーバーを常時稼働できる場所(社内サーバー、Netlify/Vercel等の静的ホスティング、
   または開発中はngrok等)にファイル一式を配置し、HTTPSでアクセスできるようにします。
   (カメラアクセスや一部PWA機能はHTTPS必須です)
2. スマートフォンのブラウザ(iOSはSafari、AndroidはChrome)でそのURLを開きます。
3. **iOS(Safari)**: 共有ボタン →「ホーム画面に追加」
   **Android(Chrome)**: メニュー(⋮) →「ホーム画面に追加」/「アプリをインストール」
4. ホーム画面のアイコンから起動すると、アドレスバーのないアプリのような画面で動作します。

## 5. 各機能のテスト方法

| 機能 | 手順 |
|---|---|
| 写真選択 | 「写真を選ぶ」からライブラリの画像を選択 / 「カメラで撮影」で撮影して直接編集開始 |
| 別の写真を選び直す | 編集中に左上の「←」を押すと確認の上ピッカー画面に戻り、別の写真を選び直せる |
| トリミング | 「トリミング」タブ→ 画面に表示された枠をドラッグで移動、四隅/四辺のハンドルでサイズ変更。アスペクト比チップ(自由/元比率/1:1/4:3/3:4/16:9/9:16)で枠の形を指定 → 「適用」で確定、「キャンセル」でこのタブに入った時点の状態に戻る |
| EXIF焼き込み | 「EXIF」タブ → 各項目チップをON/OFF(利用不可の項目は薄く表示)、位置/文字サイズ/色/縁取りを変更 → プレビューに即時反映。「キャンセル」でこのタブに入った時点の設定に戻る、「適用」で確定して次へ |
| GPS初期状態 | EXIF付き写真を選び、GPSチップが**初期状態でOFF**になっていることを確認(プライバシー保護のデフォルト仕様) |
| 顔検出 | 「隠す」タブ → 「自動検出」で人物写真を解析、検出枠が表示されることを確認 |
| 検出結果の確認/解除 | 検出枠をタップしてON/OFF切替、リストの「削除」で誤検出を除去できることを確認 |
| 手動追加 | 「＋追加」→ 写真上をドラッグしてナンバープレート等を範囲指定できることを確認 |
| モザイク/アイコン | 「隠し方」セグメントを切替え、プレビューの隠し方が変わることを確認 |
| アイコンの種類 | 「アイコン」選択時に表示されるアイコン一覧から選ぶと、既存の範囲にも反映されることを確認 |
| 非破壊編集 | トリミング後にEXIF/隠すを設定し、再度EXIFの値を変えてもトリミング結果が保持されることを確認 |
| リセット | 上部の戻るアイコン(↺)でダイアログ確認後、全編集が元画像に戻ることを確認 |
| 保存 | 保存アイコンをタップし、加工済みJPEGがダウンロード(端末では「写真に保存」相当の動作)されることを確認 |
| エラー処理 | EXIF情報のない写真を選び、「この写真にはEXIF情報が見つかりませんでした」と表示されクラッシュしないことを確認 |
| オフライン | 開発者ツールのネットワークタブで通信ログを確認し、写真ファイルを外部へ送信するリクエストが存在しないことを確認(モデルDL以外は通信ゼロ) |

## 6. 今後の拡張方法

- **ナンバープレート自動検出**: `runAutoDetect()`と同じ形で、TensorFlow.js用の物体検出モデル
  (例: カスタム学習済みYOLO系のTFJS変換モデル)を読み込み、`makeRegion(x,y,w,h,'plate','auto')`
  で登録すれば自動化できます。
- **アイコン種類の追加**: `drawIcon()`内の絵文字/描画処理を増やし、`hideMethod`の選択肢に追加。
- **ぼかし/黒塗り**: `applyHideRegions()`の分岐に`r.method === 'blur'`（CSS `filter`をCanvasに適用）
  や`'black'`（単色`fillRect`）を追加するだけで対応可能な構造にしてあります。
- **Undo/Redo・編集履歴**: `state`全体をスナップショットとして配列に積む形にすれば実装できます。
- **EXIF表示フォーマットのカスタマイズ**: `buildExifLines()`のテキスト組み立てロジックを
  ユーザー設定可能なテンプレートに置き換えます。
- **ネイティブアプリ化**: 将来的にReact Native/Flutter等でネイティブ化する場合も、
  本MVPの状態管理(`state`オブジェクト)とCanvas処理ロジックはほぼそのまま移植可能な設計にしています。

## 7. プライバシーに関する設計上の配慮

- 写真ファイルは`File`→`Image`→`Canvas`の経路のみで処理し、`fetch`/`XHR`で外部へ送信するコードは
  存在しません。
- 顔検出モデルの重みファイルのみ、初回にCDNからダウンロードします(写真データそのものは含まれません)。
- GPS情報は個人の自宅・行動範囲の特定につながるため、EXIF焼き込みの初期状態を**OFF**にしています。
